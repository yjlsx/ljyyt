# 性能优化使用指南

## 已实现的优化

### 1. ✅ 搜索结果缓存
- **功能**: 相同搜索词 5 分钟内不重复请求
- **容量**: 最多缓存 100 个搜索结果
- **策略**: LRU（最近最少使用）

### 2. ✅ 播放 URL 缓存
- **功能**: 播放 URL 缓存 20 分钟
- **效果**: 重复播放同一首歌秒开
- **自动清理**: 每 5 分钟清理过期缓存

### 3. ✅ 智能预加载
- **搜索结果**: 自动预加载前 3 首歌的播放 URL
- **播放中**: 自动预加载下一首歌
- **效果**: 切歌几乎无延迟

### 4. ✅ 性能追踪
- **监控**: 记录搜索时间、URL 解析时间
- **统计**: 音源成功率、缓存命中率
- **优化**: 根据性能数据优化音源优先级

## 技术细节

### 缓存架构

```
┌─────────────────────────────────────┐
│  用户搜索 "周杰伦"                   │
└───────────┬─────────────────────────┘
            │
            ↓
    ┌──────────────┐
    │ 检查搜索缓存  │ ← 5 分钟内有缓存？
    └───────┬──────┘
            │ 无缓存
            ↓
    ┌──────────────┐
    │ 并行搜索音源  │ ← 网易云、QQ、酷我...
    └───────┬──────┘
            │
            ↓
    ┌──────────────┐
    │ 缓存搜索结果  │ ← 存入缓存
    └───────┬──────┘
            │
            ↓
    ┌──────────────┐
    │ 预加载前 3 首 │ ← 提前获取播放 URL
    └──────────────┘
```

### 预加载策略

```javascript
// 场景 1: 搜索结果返回
搜索完成 → 预加载前 3 首 → 用户点击秒播

// 场景 2: 正在播放
开始播放 → 1 秒后预加载下一首 → 切歌秒开

// 场景 3: 重复播放
点击播放 → 检查缓存 → 命中缓存 → 秒开
```

### 缓存清理

```javascript
// 自动清理
- URL 缓存：每 5 分钟清理过期项
- 搜索缓存：LRU 策略，超过 100 项自动删除最旧的

// 手动清理
clearCaches() // 清空所有缓存
```

## FAQ

**Q: 缓存会占用多少内存？**  
A: 约 5-10MB，包括：
- 搜索缓存：最多 100 条，每条约 20KB
- URL 缓存：动态大小，通常 50-100 条

**Q: 缓存会过期吗？**  
A: 会！搜索缓存 5 分钟，URL 缓存 20 分钟（音源自己的限制）

**Q: 预加载会浪费流量吗？**  
A: 不会！只预加载用户可能点击的（搜索前 3 首 + 下一首），且有缓存去重

**Q: 可以禁用吗？**  
A: 可以，但不建议。如果需要，在控制台运行：
```javascript
window.searchCache = null
window.urlCache = null
```

**Q: 会影响旧浏览器吗？**  
A: 不会！所有功能都有降级处理，缓存失败不影响正常使用
